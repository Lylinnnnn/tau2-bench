# 训练项目代码约束

本文件约束 `project/expectation_step_rl` 后续新增、删除和拆分代码的方式。

## 固定边界

- 本项目只负责训练数据编译、单步环境执行、期待偏离奖励和训练框架适配。
- 不向 `project/trace_to_micro` 写训练代码；预实验结论和既有产物只作为只读输入。
- 不修改 τ²-Bench 的任务、数据库、工具实现和官方评测器。
- `third_party/verl` 必须保持 Git submodule，只允许通过更新 `.gitmodules` 和固定提交升级；不得复制、散落或直接修改上游源码。
- 训练代码不得导入 `trace_to_micro`。可复用的算法应在本项目中保留小而明确的实现，防止两个项目运行时互相绑定。

## 目录职责

- `data/`：把完整真实轨迹编译成离线单步决策状态；不能生成新任务或伪造轨迹。
- `tau2_adapter/`：恢复官方任务状态并执行一个动作；不能计算奖励。
- `expectation/`：匿名化、模型返回概率和 Train 校准；不能访问官方参考动作或最终奖励。
- `verl_adapter/`：只做 `verl` 接口转换；环境逻辑和信号计算必须下沉到前两个模块。
- `configs/`：只保存可复现实验参数，不放 Python 逻辑。
- `scripts/`：只编排命令和环境变量；超过一个独立算法步骤的逻辑必须进入 `src/`。
- `tests/`：目录结构与 `src/expectation_step_rl` 对齐。

## 新增、删除和拆分规则

1. 新文件必须属于上面的单一职责；无法说明归属时不新增。
2. 不新增 `utils.py`、`common.py`、`helpers.py` 等含义模糊的文件。
3. 单个源文件接近 300 行或同时包含两个可独立测试的职责时再拆分，不能为了“看起来模块化”制造空壳文件。
4. 删除或重命名文件时同步修改 README、导入、测试和启动脚本；禁止保留重复实现或兼容副本。
5. 预期内的无效候选动作可以得到明确惩罚；环境恢复、数据泄漏、打分协议和框架版本错误必须直接报错，不能静默兜底。
6. 每个新奖励项必须说明数据来源、方向、量纲、裁剪方式以及是否使用 Test 信息。
7. 每个关键边界至少有一个测试：数据划分、状态恢复、匿名映射、分数方向、框架接口。
8. `AgentLoopOutput.extra_fields` 中的奖励诊断只能放在 `reward_extra_info` 下；禁止把同名字段再复制到顶层，否则 `verl` 会用未清洗的顶层数组覆盖验证指标。
9. 正式训练只保存可推理的 LoRA adapter，必须直接写入 OSS；不得保存 FSDP 模型、优化器或随机状态分片。更改保存配置或升级 `verl` 后，先用单 step 检查确认 adapter、DataLoader 状态和最新 step 标记均已真实落盘，并确认不存在大训练状态分片；还必须实际加载基座模型和 adapter，在内存中合并并完成一次推理。
10. SwanLab 等实验平台的 API key 只能通过官方登录客户端或环境变量提供，禁止写入配置、脚本、日志和 Git。
11. 固定版本 `verl` 的兼容修复只能放在 `verl_adapter/`，并由项目训练入口显式安装；不得直接编辑子模块或服务器虚拟环境。每个覆盖点必须保持上游输入输出格式，并有针对原始故障的回归测试。

## 实验数据约束

- 优化阶段只能读取官方 Train 决策点和 Train 校准统计。
- Test 只用于冻结方案后的验证，不能回填均值、方差、阈值或超参数。
- 数据集不得包含官方参考动作、最终奖励或目标数据库状态。
- 一个样本对应一个真实轨迹中的模型决策点，不对应一个完整任务。
- 策略只生成一个候选动作；环境只执行一个动作；真实工具返回不进入策略 token loss，只用于奖励。
