# 从实验 A 到 Expectation-Step RL：证据关系与当前训练方法

## 核心结论

实验 A 证明的是：**模型在已经决定调用某个工具、但尚未看到工具返回时，其条件
概率分布中存在依赖任务上下文的“结果期待”。**

当前训练进一步研究的是：**能否从离线长轨迹中恢复真实决策状态，让当前策略只生成
一个工具动作并在真实环境中执行一次，再把工具结果相对事前期待的偏离变成 GRPO
奖励，从而改善完整长程任务能力。**

两者的关系是“信号存在性验证 → 单步奖励设计 → 策略训练”，但不是直接复现。实验 A
本身没有证明该信号可以直接用于 GRPO；当前具体奖励还依赖后续受控异常实验、
contextual min-k 分析和 Train-only 校准。

当前完整方法可以概括为：

```text
离线轨迹提供真实决策状态
→ 当前策略从同一状态采样多个单步动作
→ τ²-Bench 真实环境分别执行一次
→ 冻结模型评估真实工具结果与任务上下文是否相容
→ 将 Train 校准后的期待偏离作为候选级奖励
→ GRPO 提高较好候选的概率、降低较差候选的概率
```

它不是完整任务的 on-policy rollout，也不是完全不调用环境的纯离线 RL。更准确的
定义是：**离线状态启动、当前策略单步采样、真实环境单步执行。**

## 一、实验 A 证明了什么

实验 A 使用此前保存的 Airline 和 Retail 官方 Test 轨迹。对每个决策固定原轨迹中
已经发生的工具动作，并构造四个候选结果：

```text
真实任务历史 + 已确定的工具动作
    ├── 当前任务的真实工具返回
    ├── 其他任务中同一工具的真实返回 1
    ├── 其他任务中同一工具的真实返回 2
    └── 其他任务中同一工具的真实返回 3
```

模型不会收到“选择正确答案”的提示，而是分别计算四段候选结果的平均 token 对数
概率。成对准确率表示：真实返回和一个同工具干扰返回比较时，真实返回得分更高的
比例，随机水平为 50%。遮盖高频标识符后的主要结果为：

| 领域 | 完整真实上下文 | 仅保留工具动作 | 换成错误任务上下文 |
|---|---:|---:|---:|
| Airline | 88.2% | 69.7% | 57.9% |
| Retail | 81.3% | 60.6% | 53.1% |

这些结果支持三个判断：

1. 模型在工具返回前的概率分布中确实包含“接下来应该看到什么”的信息。
2. 这种信息不只来自工具名称和动作参数，正确任务历史有明显增益。
3. 最终失败的长轨迹也可能包含局部正确的“历史—动作—结果”关系，因此不能把失败
   轨迹中的全部步骤统一当作负样本。

实验 A 只是必要前提，不能单独证明：

- 该信号可以直接作为 GRPO 奖励；
- 模型能从一个隐藏状态直接生成精确的数据库结果；
- 信号可以检测任意真实环境异常；
- 信号能够指导模型选择正确动作；
- 使用该信号训练后，τ²-Bench 最终任务成功率一定提高。

## 二、实验 A 如何转化为当前奖励

实验 A 依靠“一个真实返回和三个干扰返回”验证排序能力，但当前策略会不断生成新
动作，不可能为每个新动作人工构造三个质量相当的干扰返回。因此当前方法进行了三个
关键转换。

### 1. 用 action-only 分布替代外部干扰返回

对当前策略生成的动作 `a` 和真实执行得到的工具结果 `o`，冻结的 Qwen3-32B 对结果
中的每个 token 计算两次概率：

```text
full_logprob(i)
= log p(结果 token i | 完整任务历史, 当前动作, 前面的结果 token)

action_logprob(i)
= log p(结果 token i | 系统说明, 当前动作, 前面的结果 token)

deviation(i) = action_logprob(i) - full_logprob(i)
```

如果完整历史支持这个结果，`full_logprob` 通常相对更高，偏离值较小；如果结果和
用户需求、前序实体、日期或状态冲突，完整历史可能压低该结果的概率，偏离值会变大。

实验 A 中“完整上下文明显优于仅动作”的观察，为这个自对照设计提供了依据。当前
训练不再需要人为构造干扰返回。

### 2. 从整段平均改为最冲突的 10% token

工具返回可能很长，大量固定字段和普通文本会稀释少数关键异常字段。当前方法将所有
token 的 `deviation` 排序，只取最大的 10% 求平均：

```text
D = 最大的 10% token 偏离值的平均
```

它重点关注错误实体、日期、状态和其他最违背上下文期待的局部内容。这个选择不是
实验 A 直接得出的，而是来自后续受控异常和 contextual min-k 实验。该分数使用
Train 数据校准后，区分 Test 干净结果与受控异常的 AUROC 为：

- Airline：0.675；
- Retail：0.787。

在同一结果的干净版本和异常版本之间，异常版本是否得到更高偏离分数的成对正确率
约为：

- Airline：78.8%；
- Retail：89.4%。

因此完整证据链是：

```text
实验 A：期待信号存在
→ 受控异常实验：期待信号会随结果异常而变化
→ contextual min-k：最冲突的少量 token 比整段平均更有效
→ 当前训练：把该偏离量转成单步 GRPO 奖励
```

### 3. 使用 Train 干净结果进行标准化

不同工具的返回长度、字段和天然语言概率不同，不能直接比较原始偏离值。当前方法先
对官方 Train 中 485 个真实、成功的工具结果计算 `D`，再按以下层级统计均值和标准差：

```text
领域 + 工具 + 返回结构
    ↓ 样本少于 5
领域 + 工具
    ↓ 仍不足
领域 + 返回结构
    ↓ 仍不足
领域
```

对当前候选结果计算：

```text
z = (当前偏离 D - Train 干净结果均值) / Train 标准差

reward = -clip(z, -5, 5)
```

含义如下：

- `z` 越大：比同类 Train 干净结果更异常，奖励越低；
- `z` 接近 0：与 Train 正常结果接近；
- `z` 为负：偏离比 Train 平均值更小，奖励为正；
- 最终连续奖励限制在 `[-5, 5]`。

校准统计只使用 Train，Test 不参与阈值、均值或标准差拟合。

## 三、当前训练的完整数据流

### 1. 从离线完整轨迹提取决策状态

数据来自此前由 Qwen3-32B 生成的 Airline 和 Retail 完整轨迹。数据编译器对每个
单工具决策截断到 Agent 即将生成动作之前，保存：

- 系统说明和领域规则；
- 用户需求与已经发生的对话；
- 此前真实工具调用和工具结果；
- 当前可用的官方工具定义；
- 用于恢复数据库状态的原始消息前缀；
- 官方 Train/Test 归属、任务编号和决策编号。

数据没有包含官方参考动作、官方最终奖励或“此处应该调用什么工具”的人工标签。
原轨迹只负责提供真实的决策起点，当前策略不需要模仿原轨迹的下一动作。

当前训练使用原始完整上下文，不使用此前 clean context/Semantic Brief 实验中的结构化
短上下文。结构化 clean data 尚未接入这套 GRPO 训练。

### 2. 当前策略从相同状态采样八个候选

当前策略是 Qwen3-32B 加 LoRA。对同一个离线状态，GRPO 独立采样八个响应：

```text
同一个决策状态
    ├── 候选响应/动作 1
    ├── 候选响应/动作 2
    ├── ...
    └── 候选响应/动作 8
```

正式配置为：

- temperature：0.6；
- top-p：0.95；
- top-k：20；
- 每个状态采样 8 个候选；
- 每批 30 个状态，名义上产生 240 个单步候选。

每个候选必须能够解析为恰好一个工具调用。

### 3. 在相同环境状态下独立执行每个候选

对每个候选，代码都会从官方任务的初始数据库开始，重放该离线决策点之前的消息和
工具历史，恢复当时的环境状态，再只执行当前策略新生成的一个动作：

```text
离线状态
→ 当前策略生成一个新动作
→ τ²-Bench 真实环境执行一次
→ 得到真实工具返回
→ 当前候选结束，不继续完整任务
```

不同候选从相同快照独立执行，不会相互污染数据库。工具结果来自真实 τ²-Bench
实现，不是语言模型猜测，也没有训练世界模型。

### 4. 冻结模型计算期待偏离

训练策略不负责给自己打分。GPU 0–3 各运行一个冻结的原始 Qwen3-32B 服务，专门
计算工具结果的 prompt logprob。

打分前会对完整历史、动作、工具定义和结果做一致匿名化。同一个原始编号在所有位置
始终变成同一个占位符，从而保留“历史订单号是否等于结果订单号”这种关系，同时减少
直接复制原始数据库编号的捷径。

策略生成动作时仍看到原始上下文；匿名化只发生在冻结奖励模型的输入中。

### 5. 无效动作、工具错误和正常结果的奖励

| 候选情况 | 当前奖励 |
|---|---:|
| 没有工具调用、多个工具调用、参数不是合法 JSON | -5 |
| 工具执行报错，如工具不存在、参数错误、前置状态不满足 | -4 |
| 没有可用 Train 校准统计 | -3 |
| 工具正常执行 | Train 校准后的连续期待偏离奖励，范围 `[-5, 5]` |

当前正式实验只有 expectation 信号：

```text
final_reward = 1.0 × expectation_reward
```

没有加入官方完整任务奖励，也没有使用唯一参考动作匹配分。

### 6. GRPO 如何更新策略

GRPO 在同一个状态的八个候选内部比较相对奖励。例如：

```text
候选 A：查询当前用户的正确订单，reward = 1.2
候选 B：查询另一个用户，reward = -0.8
候选 C：编造不存在的工具，reward = -4
候选 D：没有生成工具调用，reward = -5
```

GRPO 会提高 A 对应策略响应的概率，降低 B、C、D 的概率。如果同组八个候选的奖励
完全相同，该状态基本不产生有效的组内优势信号。

奖励施加于策略生成的整个响应，包括可能存在的思考内容和工具调用；真实工具结果
不属于策略生成内容，不会被作为 SFT 目标文本。

正式训练参数为：

- LoRA rank 32、alpha 64，作用于 all-linear；
- 学习率 `3e-6`；
- 训练 3 个 epoch；
- KL 系数 `0.001`，限制策略过度偏离基座模型；
- GPU 4–7 执行四卡 FSDP 训练，rollout 使用两卡张量并行；
- 每 10 step 保存一个可独立配合基座模型推理的 LoRA adapter；
- 每 10 step 在固定 32 个 Test 决策状态上计算一次单步奖励。

训练中的 Test 验证仍然是单步 expectation reward，不是 τ²-Bench 官方完整任务成功率。

## 四、实验 A 与训练设计的逐项对应

| 实验 A 的观察或设置 | 当前训练中的转换 |
|---|---|
| 固定离线轨迹中的真实动作 | 当前策略从同一离线状态重新采样多个动作 |
| 真实返回和三个同工具返回排序 | 不构造干扰返回，改用 action-only 概率作为自对照 |
| 完整上下文明显优于仅动作 | 用两者的 token 概率差测量上下文偏离 |
| 遮盖编号后仍存在信号 | 改成一致匿名化，同时保留实体对应关系 |
| 不同工具的原始概率不可直接比较 | 使用 Train 中同领域、工具和返回结构统计校准 |
| 最终失败轨迹仍有局部正确步骤 | 从离线局部状态学习，不把整条失败轨迹全部标负 |
| 只验证期待信号存在 | 当前进一步验证信号能否训练策略并改善完整任务 |

当前训练真正鼓励的是：

> 选择能够成功执行，而且其真实返回与当前任务历史相容的工具动作。

它没有直接保证：

> 该动作一定推动用户最终目标完成。

## 五、与最初研究动机仍有差距的部分

### 1. 当前奖励不是官方任务奖励，也不显式衡量任务进展

τ²-Bench 的一个目标可能有多条合法路径。当前方法不要求候选动作等于唯一参考动作，
因此合法替代动作不会仅因为“和参考动作不同”就被判负。

但当前方法也没有继续运行任务并检查最终目标。一个动作可能合法、返回也和上下文不
冲突，却没有推动任务完成，例如重复查询已经知道的信息。

因此当前奖励更接近“局部上下文一致性”，还不是“任务进展奖励”。重复查询、保守的
只读动作和其他容易产生可预测结果的动作，构成主要奖励投机风险。

### 2. 正式训练没有人为损坏环境返回

受控异常实验会修改结果中的实体、状态和日期；正式训练执行的是正确的 τ²-Bench
工具，环境本身不会随机返回被篡改结果。因此训练中的低奖励主要来自：

- 选错工具；
- 传错参数；
- 查询错实体；
- 动作与任务上下文不匹配；
- 工具直接报错。

这意味着当前工作已从最初的“检测环境返回是否异常”部分转向“用结果期待的一致性
指导动作选择”。两者共享同一个期待信号，但研究问题并不完全相同。

### 3. 当前方法不是隐藏状态探针

实验 A 和当前奖励都需要把真实工具结果接到前缀后面，逐 token 计算概率。它使用的
是“结果出现前定义的条件分布 + 结果出现后的逐 token 似然”，而不是直接从返回前的
一个隐藏向量解码完整结果。

因此准确表述是：

> 使用模型在结果出现前定义的条件分布，评估结果出现后的上下文一致性。

不应表述为：

> 已经从单个隐藏状态中解码出了完整期待结果。

### 4. 当前连续奖励仍可能被上下文无关动作利用

当前奖励单调鼓励 `D` 低于同类 Train 平均值。如果某个动作的结果几乎不受任务历史
影响，使 full 和 action-only 概率非常接近，它也可能获得较低偏离值和较高奖励。

所以当前分数不一定能完全区分：

```text
完整上下文明确信任、支持这个结果
```

和：

```text
这个结果本来就不需要任务上下文
```

这是必须通过完整任务官方评测，而不能只看训练 reward 上升的原因。

## 六、当前训练最终要回答的问题

当前训练不是再次验证实验 A，而是在检验一个更强的问题：

> 能否从离线长轨迹中抽取大量真实决策状态，让当前策略只做一个动作、只执行一次
> 工具，再用冻结模型的结果期待偏离作为局部反馈，通过 GRPO 改善完整长程任务能力？

训练中的 reward 和 32 状态验证只能说明模型是否在优化局部信号。最终是否改善长程
Agent，必须通过冻结 step checkpoint 后，在完整 τ²-Bench Test 任务上重新运行真实
Agent—用户交互，并计算官方 pass^1。

如果官方成功率提高，说明实验 A 中发现的期待信号不仅可测量，而且能够转化为有效的
局部训练反馈。如果训练 reward 提高但官方成功率没有提高，更可能说明当前奖励被重复
查询、无进展动作或上下文无关动作利用，而不是实验 A 中的期待信号不存在。
